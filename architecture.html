Model Layer

The agent loop never learns which brain it is talking to — Claude, hosted open-source, or a local model all arrive through one ChatProvider protocol. Embeddings never resolve at all: they run in-process.

Claude can never embed — whatever token you hold.

The Messages API is the whole surface. There is no /v1/embeddings, and no token — api_key or oauth — changes that.

We do not solve this with a provider. We solve it by not needing one. Embeddings run in-process: sentence-transformers loading nomic-ai/nomic-embed-text-v1.5, 768 dims, CPU, no network, no key, no failure mode. Memory works for every user regardless of chat provider. Cost: roughly 200MB of CPU-only torch in the image — cheaper than a second credential, a second failure mode, and a Settings screen explaining why memory silently stopped.

Not a guess. ai.metastart.friday does exactly this today — stealth/embeddings.py, nomic-embed-text-v1.5, 768 dims, into pgvector on pg17, with the comment "no API calls, no cost, ~20ms per text on CPU".

Two kinds of Claude token

Both authenticate to Claude. They are not interchangeable, and only one is the supported path.

supported

api_key

sk-ant-… from the console. Metered, billed per token. Works on every model through client.messages.create(), with native tool calling. Prefer it.

degraded

oauth

CLAUDE_CODE_OAUTH_TOKEN, a Claude Code subscription token. Full model access only through the claude-agent-sdk / CLI door.

Raw Messages-API calls with this token are throttled: Opus and Sonnet return 429, only Haiku slips through.

Evidence, from ai.metastart.friday/stealth/llm_direct.py: "the subscription CLAUDE_CODE_OAUTH_TOKEN gets full model access through the claude-agent-sdk / CLI door … whereas raw Messages-API calls with that token are throttled on the big models — Opus/Sonnet return 429, only Haiku slips through."

Resolution

Selection has no precedence and no chain. The user picks; the resolver reads their one active credential. Only chat is resolved — embeddings are in-process and always available, so they have no credential and no failure mode. The lifeboat below is an error path, not a preference ordering — it never runs while the chosen credential works.

resolver.embed()    → EmbeddingProvider  # always local

A temporary fault — 429 rate limit, 5xx, timeout, connection error — means the request errors. We are not going to answer a request with a different model at a different cost and quality and say nothing about it. A dead credential is a different case entirely — that is where the lifeboat fires, below.

The Lifeboat

An error path, not a preference ordering. It never fires while the chosen credential works — only when that credential is dead. It never changes is_active: your configuration stays yours.

temporary fault

429 · 5xx · timeout · connection

The credential is fine, the provider is not. The request errors. Retry or wait — we do not silently answer on a different model at a different cost and quality.

permanent fact

401 · 403 permission · 403 billing · 402

The credential is dead. The lifeboat fires: it answers on the user's provider = local row, sets resp.degraded, shows a UI banner, and never touches is_active. No local row → the request errors.

Your Claude key expiring, or an unpaid OpenRouter bill, must not take the assistant down. It should make it visibly dumber until you fix the bill.

Harness Decision

A harness is the agent loop: call the model, run the tool it asked for, feed the result back, repeat. Anthropic ships three — all Claude only.

Claude only

Tool Runner

anthropic SDK, client.beta.messages.tool_runner. Supplies the loop; you host it. Tools you define.

Claude only

Managed Agents

client.beta.agents / sessions. Anthropic runs the loop AND hosts a per-session container (bash, file ops, code execution). Beta.

Claude only

Claude Agent SDK

Separate package claude-agent-sdk — Claude Code as a library. Built-in file and bash tools. Supplies the loop; you host it.

None of them accept an Ollama or OpenRouter endpoint — there is no base_url that makes them talk to a local model. LangGraph is also a harness, and two harnesses cannot both own the loop.

Decision: LangGraph owns the loop. Claude is a provider.

What this costs

  • No Anthropic-hosted sandbox — we run tools ourselves.
  • No Managed Agents scheduled deployments — Phase 7 workers are ours to build.

What this buys

  • One loop, one set of tool definitions, one set of bugs.
  • Swapping the brain changes no agent code.
  • The agent behaves the same whether or not a Claude token exists.

Prior art — ai.metastart.friday

A real system runs the Claude Agent SDK as its harness and gets, for free, everything we now build ourselves in graph/nodes.py: built-in Read / Write / Edit / Bash / Glob / Grep / WebSearch tools, subagents, MCP servers (an in-process one holding 155 tools), a permission gate (can_use_tool → allow / deny), and native session resume across restarts. It is Claude-only and single-tenant — its chat brain cannot be swapped and it needs the claude CLI in the image running as non-root. That is exactly why the SDK is right there and wrong here: same SDK, different answer, because the requirements differ.

Revisit only if the local-model path is ever dropped.

Per-user tokens: pass the key explicitly — anthropic.Anthropic(api_key=cred.api_key). Never let the SDK fall back to the process environment in a multi-user service; an unset ANTHROPIC_API_KEY does not mean no credentials — the SDK also reads ANTHROPIC_AUTH_TOKEN and an on-disk auth profile, so one user's request can silently bill the host's key. friday gets away with mutating one process-global CLAUDE_CODE_OAUTH_TOKEN in os.environ — fine single-tenant, fatal multi-user.

Provider Independence

Three adapters, one brain — swap the adapter and lose nothing.

The guarantee

If Claude expires, if the OpenRouter bill goes unpaid, if you unplug the internet — the assistant keeps its memory, its history, its tools, and its identity, and keeps running on a self-hosted model.

No migration. No re-embedding. No code change. Flip the active credential.

This is a requirement, not a nice-to-have.

  1. Never persist a provider's wire format. The wire format lives inside the adapter and dies there.
  2. The encoder ships with the app. If embeddings came from OpenRouter, an unpaid bill would strand every vector in memories — you keep the rows but can no longer produce a query vector in the same space, so retrieval is dead and the knowledge is gone. Losing Claude must cost you reasoning quality, never memory.
  3. Messages are neutral. tool_calls uses our own {name, arguments} shape — not Anthropic's tool_use block, not OpenAI's tool_calls array. Ours.
  4. The graph asks what the provider can do. ChatProvider.capabilities() returns max_context_tokens, native_tools, streaming, json_schema. Memory retrieval budgets against the ACTIVE provider's window, computed at request time and never at boot — a retrieval sized for Claude's 1M window overflows a local 8k window on the exact turn you fall back to it. When native_tools is false, the tool loop asks for JSON and parses it.
  5. The fallback you never test is not a fallback. CI runs the full agent suite against Ollama on every commit — same tests, same tools, same memory assertions. Local is the floor, and the floor has to hold on the day the paid providers are gone.

The lifeboat

try:
    return resolver.chat(user).chat(messages, tools)
except (AuthenticationError, PermissionDeniedError, InsufficientCredits):
    lifeboat = resolver.lifeboat(user)
    if lifeboat is None:
        raise
    resp = lifeboat.chat(messages, tools)
    resp.degraded = "Claude credential rejected. Answered by local llama3.1."
    return resp

429 rate limit, 5xx, timeout, connection error. The credential is fine, the provider is not. The request errors. We do not answer with a different model at a different cost and quality and say nothing about it.

Permanent fact

401 authentication_error, 403 permission_error, 403 billing_error, 402 where the provider uses it. The credential is dead. The lifeboat fires.

  • Only on a dead credential — never on 429, never on 5xx, never on a timeout.
  • Never silent — resp.degraded is set, the UI shows a banner, and the answering model is recorded on the turn.
  • The lifeboat never changes is_active — the user's configuration is theirs.
  • No lifeboat configured means the request errors, same as before.

Honest limits: prompts tuned for Claude underperform on a small local model; anthropic_cli has no native tools, so the Claude OAuth path is already the degraded path; and local models vary wildly at tool calling — pin one that can do it and put its name in the config, not in someone's head.

How retrieval works

  • Embeddings run in-process — sentence-transformers loading nomic-ai/nomic-embed-text-v1.5, 768 dims, on CPU, with no network and no key.
  • So memory works for every user no matter which chat brain they configured — and Claude can never embed, whatever token you hold, which is exactly why we don't ask it to.
  • Store the vector in the memories.embedding column in pgvector.
  • Retrieve the top-k nearest memories by cosine distance for a query, and inject them into the agent's context to ground its response.
  • Retrieval budgets against the active chat provider's max_context_tokens, computed at request time — a retrieval sized for Claude's 1M window overflows a local 8k window on the exact turn you fall back to it.

embedding is vector(768) for nomic-embed-text-v1.5. The dimension is fixed by the model, so changing models means altering the column and re-embedding every row. Embeddings: src/llm/embeddings.py · retrieval: src/memory/retriever.py.

Background Workers

Long-running jobs run outside the request path, driven by an async Redis Stream pipeline.

Email monitoring

Polls the Gmail integration in the background and raises a notification when new mail arrives.

Scheduled tasks

Time-triggered jobs that the worker picks up from the stream and runs off the request path.

Daily summaries

Runs on a schedule to compile a summary, then pushes it to the user as a notification.

Data Model

PostgreSQL + pgvector — five tables across three services, linked by foreign keys.

Ownership: users + provider_credentials — User Service (Go) · conversations + messages — Conversation Service (Go) · memories — Memory Engine (Python), whose embedding column is the pgvector vector and whose embedding_model records the encoder that produced it. In provider_credentials, api_key_enc is encrypted at rest and never returned by the API, and exactly one active row is allowed per user. At most one row is allowed per (user_id, provider), so an inactive local row can sit alongside an active Claude one and serve as the lifeboat.

Findings in Friday

All but the last are in stealth/ocr.py, the one place that calls the raw Anthropic API. Nothing here affects this plan; it surfaced during the read.

  1. Dated model snapshot. claude-haiku-4-5-20251001 is pinned to an October 2025 snapshot. Snapshots get retired and start returning 404. The unsuffixed alias is durable. ocr.py:43
  2. stop_reason is never checked. A max_tokens truncation at 4096, or a refusal, is silently accepted as complete OCR text. ocr.py:172
  3. Bare except Exception, no retry. No typed SDK errors are caught, so a transient 429 or 529 permanently downgrades the request to local pytesseract. The SDK path in llm_direct.py backs off; this one does not. ocr.py:169
  4. No image downscaling. Only a 10 MB byte cap — no pixel or megapixel guard. A within-budget high-resolution image is sent as-is, which can 400 or waste tokens. ocr.py:22, :259
  5. The production chat model is unpinned. CLAUDE_MODEL defaults to the empty string, so the main agent runs on whatever the CLI happens to default to. config.py:78

Clean by inspection: no budget_tokens, no temperature/top_p/top_k, no assistant-turn prefill, no base_url override, and nothing anywhere assumes an Anthropic embeddings endpoint.
